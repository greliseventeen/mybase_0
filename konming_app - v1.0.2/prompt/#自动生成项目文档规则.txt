#自动生成项目文档规则
【全局约束上下文 — 本次及后续所有对话强制执行】

一、自动生成项目文档规则

从本次对话开始，每次执行重大功能版本文件变更时，你需要自动生成一份增量式项目全局上下文更新说明；每次在该版本下进行代码级报错修正时，你需要自动生成一份纠错日志。

1. 文件类型选择：
   - 若是新增功能、模块重构、页面优化等正向变更，生成【更新说明】
   - 若是修复编译错误、运行时崩溃、逻辑 Bug 等纠正性变更，生成【纠错日志】

2. 描述重点：
   - 分点描述当前变更相较于上一个版本的改动内容
   - 执行代码级报错修正时，需要记录：错误现象 → 排查过程 → 修复方案 → 涉及文件及改动位置
   - 重要改动单独成一个模块描述，包含修改文件清单、关键代码位置、验证结果

3. 命名方式及条件：
   - 版本改动：【Vx.x.x 更新说明】（如【V1.0.1 更新说明】）
     * 第一级版本号（x.0.0）：App 级全面升级（修改前必须询问开发者确认）
     * 第二级版本号（0.x.0）：模块级/页面级全面升级（修改前必须询问开发者确认）
     * 第三级版本号（0.0.x）：模块页面中的小功能级别 & Bug 修复级别（自动递增，无需询问）
   - 代码纠错：【Vx.x.x 纠错日志x】（如【V1.0.1 纠错日志1】）
     * 版本号与当前版本号保持一致
     * 纠错日志号从 1 开始自增，每次代码纠错时生成

4. 文件保存路径：konming_app/prompt/
   - 更新说明示例：konming_app/prompt/V1.0.1 更新说明.txt
   - 纠错日志示例：konming_app/prompt/V1.0.1 纠错日志1.txt

5. 生成时机：
   - 每次对话结束前，若对话中产生了代码变更，自动判断类型并生成对应文档
   - 对话中若多次纠错，可生成多个纠错日志文件（日志号递增）

三、执行原则
- 每次对话的代码变更必须先获得开发者同意再实施
- 新增或修改文件时，自动将子页面文件放入对应的二级/三级子包
- 所有 XML 代码使用 Markdown 代码块输出，保留原始尖括号，禁止 HTML 实体转义
- 优先提供改动片段和插入位置，而非完整文件覆盖
